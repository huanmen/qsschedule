# 插件后台管理

在项目根目录执行 `powershell -File Start-Plugin-Admin.ps1 -Server 用户名@服务器`，打开 <http://127.0.0.1:18474/>。可通过 `QSS_DEPLOY_SSH` 环境变量配置 SSH 别名或主机；默认连接项目域名。页面的数据目录应为 `/var/lib/qsschedule`，保存和发布会操作服务器资料。服务只监听服务器本机，关闭 SSH 隧道后可再次启动。

如需仅编辑本机副本，先关闭现有 SSH 隧道，再运行 `powershell -File Start-Plugin-Admin.ps1 -Local`；本机目录为 `server/qsschedule`。启动器仅会自动关闭经核实属于本项目的本机预览服务，不会关闭其他端口占用者。本机草稿不会自动同步到线上。

## 使用

- **添加插件**：填写稳定 ID、名称、简介和版本；新插件支持宿主 v1/v2 格式的广告规则数据包。上传 JSON 或填写公开 HTTPS 规则直链，再保存草稿。
- **修改赛事资料**：选择“赛事与考证”→“规则与资料”，搜索赛事名称、ID 或资料文字，逐字段修改当前/往届资料、时间节点、来源、核对日期和更新渠道。可添加、复制、删除条目。“资料包其他字段”可以编辑别名等全局内容。
- **修改内置规则**：选择“广告辅助”，搜索应用或规则后编辑匹配条件、文字、控件和参数。初始化使用从当前宿主编译规则导出的 `adskip-rules.json`。内置通用引擎和受保护的绘制结构规则需在宿主中维护；后台会拒绝覆盖，其余资料规则可编辑。
- **完整 JSON**：切换到完整 JSON 编辑，或在逐字段视图中选择“修改此段 JSON”，以增删嵌套字段、数组和来源。导入与导出支持完整资料包。后台不会自动抓取填写的外部 URL。
- **准备新版本**：增加插件版本，并同步资料包版本。已发布版本的数据包不可替换；内容变化需要更高版本。只改名称、简介和更新说明可以沿用版本。
- **保存草稿**：不会改变市场中的已发布快照。每次保存留下记录；多窗口同时修改时，旧窗口会提示重新载入，防止覆盖新修改。
- **发布 / 下架**：发布将草稿变为市场版本；下架停止展示和分发包，已安装用户的数据保留。下架后可重新发布。旧版本号不能覆盖不同资料，也不能低于历史最高版本。
- **版本记录**：恢复历史内容为草稿；检查版本号并保存，再决定是否发布。旧资料包按 SHA-256 保存，恢复历史不依赖当前上传文件。
- **市场预览**：只显示已发布快照。刷新会重新读取数据；离开未保存页面会提示。

赛事资料中的事实、来源、核对日期由管理者维护；JSON 结构校验不能替代事实核实。规则包在 App 安装时仍需通过完整的规则兼容性检查。新原生页面、功能和执行代码必须先接入宿主并重新构建，后台不能下发原生代码。

## App 联动

新宿主市场读取 `GET /api/plugins`，展示已发布名称、简介、版本及最低宿主要求，并自动展示官方规则插件。下架且未安装的插件隐藏；已安装的显示“已下架 · 保留已安装版本”，仍可使用、置顶和删除。市场支持手动刷新；网络失败保留最近目录。赛事资料通过 `https://huanmen.com.cn/qsschedule` 下载，宿主验证 SHA-256 后保存；日历仅在插件已安装时显示“赛事与考证”筛选项。

已安装的下架规则条目保留在本机归档中，方便删除。官方目录与用户自己添加的同 ID 来源冲突时，保留用户来源的管理入口。下架不是远程卸载，已下载资料和用户手动导入的本地文件不会删除。

公共接口还包括 `GET /api/plugin-rules-catalog`、`GET /api/plugins/<id>`、`GET /api/rules/adskip` 和已发布 JSON 的下载路由。启用管理数据库后，这些接口以已发布快照为准；资料下载保留原始字节，SHA-256 与元数据一致。旧版本 APK 的固定卡片可能仍展示，但相应服务端资料端点不再分发下架内容；内置离线功能需要新版宿主才按市场状态隐藏。

## 服务器使用

将 `plugin_admin.py`、`plugin_store.py`、`plugin-admin/`、`adskip-rules.json` 与更新后的 `app.py` 部署到原服务的代码目录。管理服务和公共服务必须使用同一个 `QSS_DATA`。赛事原始资料包和元数据首次导入时需位于该数据目录，沿用现有 `downloads/` 路径。

可使用 `qsschedule-plugin-admin.service`（路径及服务用户按实际部署调整）。保持管理端口只监听 `127.0.0.1:18474`；现有 Nginx 公共路由不代理管理端口，不需要放大公共上传限制。

```sh
ssh -N -L 18474:127.0.0.1:18474 用户名@服务器
```

然后打开 <http://127.0.0.1:18474/>。同端口转发保留 Host 校验。后台不使用独立网页密码，访问依赖本机权限或 SSH 身份验证；Host、Origin、Fetch Metadata 和每进程 CSRF 校验限制跨站访问。不要将管理端口作为公开网站代理。

备份整个数据目录，至少包含 `plugins.sqlite`、其 WAL 文件和 `plugin-packages/`。运行中请使用 SQLite 在线备份工具，或停止两个服务后复制；不要单独复制正在写入的数据库主文件。资料包按内容寻址，保留全部历史文件以支持恢复。

浏览器：`python docs/qa-plugin-admin.py`，使用独立临时目录，不发布或修改用户真实资料。覆盖赛事字段编辑、版本同步、草稿隔离、发布/下架、新规则添加、JSON 错误处理、历史恢复、内置规则修改和 390/768 px 布局，证据位于 `docs/plugin-admin-qa/`。

宿主：`:app:testDebugUnitTest`、`:app:assembleRelease`。后台初版构建记录 `docs/oct14-plugin-admin-build.log`；后续日历及部署验证见 `OCT14-ONLINE-PLUGIN-CALENDAR.md`。

后台初版验收：17 项服务端测试、204 项 App 单元测试及浏览器完整流程均通过；390/768 px 没有横向溢出，浏览器没有脚本错误。测试添加和发布均在临时目录完成。

部署信息、管理员身份和备份位置由部署者自行管理，不包含在公开源码中。修改资料前请做数据库在线备份并保留 `plugin-packages/`。
